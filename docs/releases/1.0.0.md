## How the APK in the release was made

1. GitHub Actions built the release variant on a 7 GB runner (`workflow_dispatch`, `minify=false`).
   The 2 GB development container cannot do this: `:app:mergeDexRelease` is killed by the kernel
   and Gradle reports only *"the daemon disappeared"*.
2. `scripts/resign-apk.sh` removed CI's debug signature (`zip -d`, never unzip+re-zip — that would
   re-compress `resources.arsc` and Android 11+ refuses such an APK), re-aligned it, and signed it
   with `android/afnews-release.jks`, so the artifact carries the same identity as a locally built
   one and stays upgradable.
3. The signed file was verified, then uploaded. A second asset
   (`afghanistan-news-1.0.0-debug-key.apk`) keeps CI's own output for provenance — CI has no
   keystore, so its APK is debug-signed. The asset name says which key signed it; the pipeline no
   longer `--clobber`s across signing identities.

## Bugs found and fixed on the way here

| Symptom | Cause | Fix |
|---|---|---|
| Every article in every list came back as `"id": ""` and could not be opened | `store.InsertArticle` accepted an empty `ArticleInput.ID` and stored it | the store derives the stable id the ingest pipeline uses; regression test `TestInsertArticleMintsMissingID` |
| Console rendered `undefined`; acceptance check *feed row contract* failed | `model.Feed.LastCheckedAt` is `omitempty`, so a never-polled feed dropped the key | `feedRow()` guarantees the full contract with explicit nulls; regression test `TestAdminFeedRowContractIsStable` |
| Backoff reached 7h8m against a documented 6h cap | jitter was applied *after* the clamp (cap × 1.2) | jitter first, clamp last, with an explicit floor; the test now draws 700 times against the bound |
| Fresh CI database failed exactly 3 acceptance checks | no content to serve | `cmd/seed-fixtures` + `scripts/seed-and-verify.sh`; CI seeds before the suite |
| A fresh install landed on an empty Home with no explanation | §7.1 "route to onboarding or Home" was never rendered — the flag existed, the screen did not | `OnboardingScreen`: network-free, reads the packaged OPML, shows the real numbers, three languages, optional server step |
| Language could not be changed; every row said "فعال" | the Settings rows were static | rows reflect the stored language and switch it |

## Repeating this release

```bash
bash scripts/seed-and-verify.sh                      # empty database → 48/48
cd android && ./gradlew :app:assembleDebug testDebugUnitTest
gh workflow run release-apk.yml -f minify=false      # or: push a tag v*
bash scripts/resign-apk.sh app-release.apk release-apk/afghanistan-news-<v>-signed.apk
```

`docs/android/release.md` documents the build routes, the signing order and the first-run flow.
